# Task 010I — Приближённый сбор OSM-кандидатов

Статус: реализовано и проверено локально 2026-09-14.
Основание: согласованное упрощение 010H для восстановления примерного пути по лесу.

## Проблема

010H отказывал Andromeda G2 из-за нескольких практически равнозначных проекций
records 1786–1788 на изгиб одной дороги. Расхождение вдоль дороги около 3 м не должно
блокировать построение гипотезы маршрута при допустимой погрешности десятки метров.
Наличие нескольких дорог также должно давать варианты для последующего выбора.

## Реализация и границы

Core включает `RouteAlternativesRequest.approximate_candidates=True`. Строгий режим
остаётся default для прямых typed вызовов routing и сохраняет контракт 010H.

- Допускаются привязки опор на расстоянии до 100 м.
- Равнозначные локальные проекции в пределах 20 м вдоль одной дороги объединяются.
  Это не объединение разных дорог или разрывов графа.
- Контекст ранжирует дороги; неоднозначные проекции отдельных точек игнорируются.
  Для контекстного ранжирования нужны минимум восемь пригодных точек и доля 0.6.
  При недостаточном контексте используется расстояние до опоры, без отказа дороги.
- Проверяются до двух групп дорог на каждой опоре и четырёх пар. На каждую пару
  запрашиваются native alternatives: при двух alternatives это до 12 маршрутов.
- Каждая гипотеза проходит прежний аудит геометрии, направлений, доступности и
  последовательности рёбер; крайние рёбра должны принадлежать выбранным группам.
- Ошибка аудита отдельной гипотезы отражается в диагностике и не удаляет другие
  проверенные гипотезы. Ошибки backend и общего бюджета завершают всю операцию.
- Маршруты дедуплицируются; для них сохраняются варианты привязки, соединения с
  исходными опорами, контекст и отдельная уверенность гипотезы MEDIUM/LOW.
- HTML показывает кандидатов и диагностику, включает OSM-слои в preview по умолчанию.

Новые пороги именованы в RoutingConfig и входят в query policy; перестройка графа
не требуется. Сантиметровые технические проверки целостности данных графа сохранены:
они проверяют соответствие ответа движка графу, а не точность GPS-привязки спортсмена.

Не реализованы: автоматический выбор GPX/OSM, применение приближённых кандидатов к FIT,
изменение detector, mask, timestamps или исходных правдоподобных координат, DEM,
сбор контекста через пропуски, общий map matching, web deployment.

## Acceptance criteria и проверки

Все критерии выполнены:

1. Близкие проекции на одной дороге не блокируют поиск; существенно разнесённые
   проекции не сливаются. Проверено синтетическим тестом изгиба и петли.
2. Несколько дорог дают несколько аудированных кандидатов; native alternatives
   сохранены. Проверены синтетические native графы и реальные треки.
3. Без контекста доступны LOW-гипотезы; привязка 55 м принимается, за 100 м исключается.
4. Ограничения пар, общий бюджет, ошибки отдельных маршрутов, дедупликация и
   воспроизводимость покрыты тестами. Ошибка бюджета после успеха не выдаёт partial.
5. Строгие API и предыдущие тесты проходят. Добавлены 12 тестовых случаев в
   `packages/osm-routing/tests/test_approximate.py`, включая валидацию конфигурации.
6. Core: 571 passed, 17 skipped (недоступные private fixtures). Routing: 450 passed.
   Mypy Core (51 файл) и routing (22 файла), Ruff проходят.
7. Все пять приватных прогонов завершились успешно. Проверены неизменность хешей
   десяти исходных FIT/GPX и отсутствие записи FIT. В браузере проверены видимость
   OSM-слоёв и отсутствие JavaScript errors.

Артефакты: игнорируемая директория `tests/private/osm-dry-run-20260914/approximate-final`.
`runs.json` содержит команды, статусы и контроль исходников; `run.py` повторяет прогон.
Все команды используют `--min-confidence medium` для GPX preview; OSM остаётся discovery.

Andromeda G2 (records 1794–3254): 12 кандидатов, primary 2563 м, MEDIUM.
Это 12 вариантов геометрии, включая длинные обходы, а не 12 равноценных восстановлений.
Поиск ограничен и не гарантирует нахождение фактически пройденного пути; primary
не означает доказанный маршрут или автоматическое разрешение записи в FIT.
