# Task 012E — GPX-first и автоматическое применение OSM

Статус: реализована и проверена локально 2026-09-14.
Зависимости: 010I, 012B, 012D. Следующий этап: web integration 012C.

## Продуктовый сценарий первой версии

Пользователь загружает FIT и GPX и получает исправленный FIT с отчётом.
Система самостоятельно выполняет:

1. Независимую от course/OSM детекцию и очистку проблемных координат.
2. GPX-first: применение пригодного GPX-кандидата по действующим правилам.
3. Для оставшихся разрывов — автоматический выбор и применение пригодного OSM-пути.
4. Единую запись FIT и отчёт о фактических изменениях и оставшихся пропусках.

Ручного выбора, selection-файлов, обязательных подтверждений и экранов согласования
маршрута в первой версии нет. Возвращаться к такому UX только по отдельному решению
пользователя на основании реальных случаев, с которыми автоматика не справляется.

## Изменение относительно предыдущих этапов

Совместный сбор GPX/OSM из 010I сохраняется. Сбор и применение имеют разные правила:
наличие принятого GPX решает выбор источника независимо от score OSM. Наличие
GPX-кандидата, который не прошёл применение/порог, не блокирует OSM fallback.

Общий advisory ranking 012D остаётся диагностикой. Ничья GPX/OSM в нём не блокирует
GPX-first. Для Andromeda G2 при пригодном GPX применяется GPX; выбирать OSM ради
разрешения межпровайдерной ничьей не требуется.

Для OSM нужен автоматический selector среди доступных кандидатов одного разрыва.
Не ограничиваться `recommended_candidate_id` 012D: близкие оценки должны допускать
выбор разумного примерного пути по детерминированным дополнительным правилам.
Использовать качество привязок, контекст, направление, пригодные сигналы дистанции
и длину пути; избегать бессмысленных длинных обходов. Отдельно специфицировать
порядок разрешения равенств и явно слабых вариантов перед реализацией.

Основа application — allocation, timing и atomic writer из 012B. Автоматический
выбор получает собственный provenance `automatic_osm_selection`; не подделывать
`OSMRouteConfirmation` и не утверждать, что пользователь подтвердил путь.
Старый confirmed API может остаться совместимым, но не является продуктовым потоком.

Допуски применения должны соответствовать приближённой лесной модели 010I:
не переносить автоматически старый 5-метровый connector gate и требования доказанной
route identity. Конкретные application defaults и проверки согласованности сигналов
зафиксировать перед кодом; не ослаблять detector, маску записи и timestamps.

Если первый кандидат не проходит application, проверить следующие в пределах
бюджета. При отсутствии пригодного пути оставить gap unresolved, вернуть частичный
результат без запроса ручного выбора. Низкое качество пути и физическую
невозможность отражать отдельными причинами в отчёте.

## Критерии результата

- Два входных файла → исправленный FIT, без промежуточного пользовательского выбора.
- Принятый GPX сохраняет приоритет, включая ничью GPX/OSM в advisory ranking.
- Непригодный GPX не блокирует автоматически выбранный пригодный OSM.
- Близкие OSM-варианты разрешаются воспроизводимо, порядок discovery не выбирает путь.
- Неудача применения одного OSM-кандидата допускает проверку следующего.
- Нет пригодного OSM → partial/unresolved, успешные GPX repairs сохраняются.
- Один writer, неизменные timestamps и preserved records, полный FIT diff.
- Provenance различает автоматическую гипотезу и исторический confirmed API.
- Синтетические тесты и повторный прогон реальных пар с комментариями к геометрии,
  фактическим применённым источникам и причинам отказа.
- Web 012C использует этот Core-контракт и не добавляет собственную логику выбора.

В этом этапе не реализовывать ручной CLI/UI, DEM и deployment.

## Правила реализации 012E

- Ранжировать OSM отдельно от GPX. Допустим score ≤5 и минимум два наблюдаемых
  компонента по 012D. Ничья разрешается полной геодезической длиной с connectors,
  затем route ID; порядок discovery и прежний primary не влияют.
- Проверять до 64 вариантов на gap, не более 100000 route points на activity и
  10000 records на gap. Применять первый вариант, прошедший все gates; failures
  каждого испробованного пути сохранять. Ограничения ranking 012D также действуют.
- Application: connector ≤100 м; для выбора профиля OSM distance/speed бюджет
  расхождения — max(100 м, 20% длины). После уточнения на G6 это advisory-проверка,
  а не запрет маршрута. GPX использует свои именованные допуски выбора профиля.
  При несовместимой телеметрии используется активное время. Существующие active time /
  per-transition speed gates и запрет изменений timestamps сохраняются. Не менять
  altitude/distance на основании OSM; allocation проверяет distance, speed, затем time.
- Автоматическая гипотеза имеет MEDIUM. CLI с --osm-graph-id использует MEDIUM,
  если --min-confidence не задан; без OSM сохраняется старый HIGH. Явный HIGH/LOW
  не переопределять. Invalidation defaults не меняются.
- Нет подходящего OSM, ошибка backend или исчерпание бюджета: сохранить пригодный
  GPX и очистку, вернуть диагностированный partial. Никаких фиктивных confirmation.
- dry-run и запись используют один и тот же итоговый план. JSON/HTML содержат
  автоматические решения, ranking исходных кандидатов и результаты единственного writer.

## Реализация и проверка

Core API `apply_automatic_osm_routes` возвращает итоговый RepairPlan. CLI вызывает
его после совместного discovery/ranking и перед единственным atomic writer.
Пригодность GPX/OSM дополнительно проверяется на квантованных координатах FIT до
выбора; отказ допускает следующий OSM. Сохраняются исходные причины unresolved GPX.
`OSMPathProvenance.confirmation=None` и `identity_basis=automatic_osm_selection`
явно отделяют автоматическую гипотезу от старого совместимого confirmed API.

22 новых синтетических проверки: GPX-first, LOW/неприменимый GPX, рейтинг и длина
против primary/discovery order, retry и лимиты, некорректные anchors/geometry/audit,
допуски, thresholds, запись FIT, determinism, clock/pauses/events, parity CLI dry-run/write,
отказ backend с сохранением GPX. Обновлены две проверки старого dry-run-only CLI.

## Уточнение по G6: непроверенная дистанция — advisory evidence

По решению пользователя политика автоматического применения обновлена до
`gpx-first-automatic-osm-v2`. Проверка физической правдоподобности сигнала не
подтверждает его точность или независимость от GNSS. Несовпадение с длиной пути
больше не блокирует GPX/автоматический OSM само по себе.

- Общий `allocate_signal_progress` проверяет профили distance/speed и использует
  подходящий по длине и скорости профиль. Несовместимый профиль получает диагностику;
  далее проверяется следующий, затем равномерное активное время.
- Подтверждённые паузы, отсутствие активного времени, непригодные timestamps,
  чрезмерная скорость пути/переходов остаются ограничениями. Не увеличивать время.
- Новые GPX-кандидаты, допущенные вопреки конфликту/непригодному профилю, имеют
  MEDIUM. Прежняя уверенность уже допустимых GPX без конфликтов не меняется.
- GPX получает ограниченный штраф в оценке привязки: максимум
  `signal_path_score_penalty_m=10` метров matching score. Штраф растёт с превышением
  бюджета, нормированным на длину; берётся максимум по двум сигналам, а не сумма.
  OSM сохраняет существующий distance penalty общего ranking 012D и quality gate.
- При расхождении сохранённой дистанции и геометрии отчёт отмечает distance quality
  как uncertain. Provenance хранит сигналы, расхождение, метод allocation и оценку.
- Контекст достоверных точек вокруг разрыва, detector/mask и исторический confirmed
  API не меняют политику из-за этого уточнения. Совпадение GPX/OSM не считается
  доказательством фактически пройденного маршрута.

Пять новых синтетических тестов и обновлённые проверки старого veto: GPX/OSM с
недосчитанной дистанцией и записью FIT, bounded penalty без двойного голоса,
непригодный профиль/невозможное время, GPX-first. Проверены паузы и fallback speed/time.
Итог: **612 passed, 17 skipped**; mypy/ruff passed. Команды проверки выше.
