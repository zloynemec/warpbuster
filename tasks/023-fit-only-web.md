# Task 023 — FIT-only Web Integration

Статус: 023A–023C завершены 2026-09-18; реализация и Web acceptance приняты.
Исходная предпосылка: [Task 022](022-fit-only-reconstruction.md) завершена и
принята по pipeline/CLI tests и внутренним JSON/HTML отчётам. По прямому указанию
пользователя 023A–023C выполнены до формального завершения приёмки 022D.
Это согласованное исключение к предпосылке не означает принятия всей 022;
результаты Web acceptance приведены в разделе 10.

## 1. Цель и границы

Добавить в Web принятый в 022 режим восстановления по одному FIT без GPX.
Использовать одну существующую страницу `/fix`: FIT обязателен, GPX необязателен.
Ручные старт/финиш и общая точка кольца вынесены в
[Task 024](024-web-start-finish-input.md).

023 интегрирует готовый общий pipeline. Coverage, detector, OSM/DEM selection,
allocation и FIT writer не реализуются заново в Web. Поведение определяется
завершённым contract 022, включая порог 51% по активному времени только без GPX
и неизменяемые timestamps/сохранённые координаты.

До начала 023 существующий Web уже работает с обновлённым pipeline через прежний
FIT+GPX вызов. Совместимость этого вызова — acceptance 022, а не исправление в 023.

Сохранить последовательность «загрузка → обработка → результат». Промежуточного
анализа с ожиданием ввода точек в 023 нет. В FIT-only допустимые внутренние gaps
восстанавливаются; отсутствующие prefix/suffix остаются unresolved. Это ограничение
не распространяется на прежний FIT+GPX workflow.

## 2. Форма и API

- Блоки FIT и GPX сразу видны и одинаково заметны. GPX не сворачивать и не делать
  визуально второстепенным: если маршрут есть, его стоит добавить — он существенно
  помогает восстановлению. Подпись «Необязательно» объясняет возможность запуска
  без него, а не снижает его значимость.
- Пример пояснения GPX: «Если есть GPX маршрута, добавь его — он значительно
  поможет восстановить повреждённые участки и пропуски координат».
  Не обещать исторически точный результат и не считать отклонение от GPX сбоем.
- После выбора пригодного FIT запуск доступен без GPX. Обновить тексты «оба файла»
  и «выбрано из 2»; счётчик двух обязательных файлов больше не определяет готовность.
- Отдельного выбора режима нет: наличие GPX определяет прежний FIT+GPX сценарий,
  отсутствие — FIT-only. Удаление GPX до отправки снова позволяет запуск с одним FIT.
- Ручных точек в форме, публичном API и новых job metadata нет. Прямые запросы
  с `start`, `finish`, `loop_point` и другими неподдерживаемыми полями отклонять,
  не игнорировать молча. Worker не передаёт endpoint hints в Core.
- Сохранить проверку дублей/неизвестных полей, типов файлов и upload/resource
  ограничения. Optional GPX означает отсутствие файла, а не разрешение на пустой
  или неподходящий файл.
- Предоставленный невалидный или пустой GPX остаётся ошибкой GPX и не переключает
  запрос молча в FIT-only. Не создавать фиктивный `course.gpx`.

## 3. Job, worker и конфигурация

Persisted job metadata явно хранит наличие course, достаточное для повторения
запроса. Worker передаёт входные файлы в принятый pipeline 022; отсутствие GPX
передаётся явно. Режим и coverage разрешает Core, не Web-эвристика.

Сохранить обработку прежних двухфайловых jobs без новых metadata полей. Для retry,
refresh и повторного чтения результата не менять режим. Обновить предположения
об обязательном GPX во всех затронутых Web adapters.
Повторная пользовательская загрузка после отказа создаёт новый job; добавление
GPX к уже загруженному FIT без повторной загрузки не входит в 023.

Добавить серверную настройку `minimum_observed_gps_coverage_percent` с default 51%,
общей с Core validation и действием только на FIT-only. Дополнительные параметры
coverage передаются согласно принятому config 022. Пользовательский Web-регулятор
порога не требуется. Сохранить существующие OSM/DEM defaults, isolation и budgets.

## 4. Публичный результат и приватность

Обновить allowlisted public schema и её frontend consumer согласованно. Не
сериализовать внутренний Core report целиком. Результат показывает:

- режим, статус coverage gate, исходную долю GPS и требуемый порог;
- активную и покрытую GPS длительность, причины невозможности расчёта;
- исходные/восстановленные участки и статусы internal/prefix/suffix gaps;
- approximate/partial результат, причины отказов и доступные validation/diff
  сведения в рамках публичной проекции.

При `below_threshold`/`unavailable` не выдавать ссылку на несуществующий corrected
FIT. Браузер, запустивший обработку, возвращается на `/fix`; сообщение об отказе
сохраняется после перехода, оба поля файлов пусты. Для повторной попытки пользователь
выбирает FIT заново и добавляет GPX. Не подставлять старый FIT и не создавать
механизм дополнения завершённого job новым файлом.

Пример сообщения `below_threshold`: «Для восстановления без GPX недостаточно
сохранившихся GPS-данных: {coverage}% активного времени при минимуме {threshold}%.
Выбери FIT повторно и добавь GPX маршрута». Значения берутся из результата Core;
сравнение с порогом не выполняется по округлённому значению UI.

Для `unavailable`: «Не удалось определить покрытие GPS по времени записи.
Восстановление без GPX не запущено. Выбери FIT повторно и добавь GPX маршрута».
При наличии пригодной публичной причины показать её понятным текстом.
`unavailable` не означает 0%; с GPX gate — `not_applicable`. Диагностика отказа
сохраняется в результате job; возврат на форму не удаляет её. Не отправлять на
`/fix` посетителя, отдельно открывшего существующий отчёт по ссылке.

Отказ одного gap не маскирует успешно восстановленные другие участки. Не называть
результат полным или точным, если это не следует из принятого contract.
Частичный результат с успешной записью и проверками доступен для скачивания;
рядом показывать оставшиеся разрывы. Для отсутствующих краёв в FIT-only объяснить:
«Начало/конец записи остались без координат: для их восстановления не хватает
данных». Не предлагать пока недоступный ввод точек. Частичный результат сам по себе
не вызывает возврат на `/fix`.

Сохранить существующие контроль доступа, retention и запрет чувствительных логов
для однофайловых jobs. Не раскрывать приватные данные в параметрах URL возврата.
Публичные errors не раскрывают private paths, сырые config или exception dumps.

## 5. Этапы и предполагаемые файлы

1. **023A — Web backend:** optional GPX upload, validation, persisted metadata,
   worker/config и совместимость прежних jobs.
2. **023B — UI/public reports:** одна форма с двумя равно заметными блоками,
   публичная схема и карта результата без ручных точек; отказ по coverage с
   возвратом на `/fix`, состояния partial и понятные сообщения об ограничениях.
3. **023C — Acceptance:** backend/frontend tests, end-to-end и локальный browser
   smoke, regression прежнего FIT+GPX workflow.

Ожидаемые области изменений: `web/backend/warpbuster_web/`, Web frontend,
`web/tests/`, frontend tests и Web documentation. Обновить также пояснения на
главной странице и в FAQ: прежнее требование двух файлов больше не действует.
Изменения общего Core допустимы только для выявленной интеграционной необходимости
с сохранением acceptance 022; новые reconstruction policies не входят в 023.

## 6. Acceptance criteria

1. Предпосылка 022 подтверждена отчётом реализации и приёмкой внутренних отчётов.
2. Одна страница `/fix` принимает FIT или FIT+GPX; оба блока видны сразу и одинаково
   заметны, FIT достаточно для запуска. Отсутствующий course не приводит к
   обращению к фиктивному файлу. Удаление GPX не блокирует запуск с FIT.
3. Невалидный/пустой GPX даёт понятную ошибку без скрытой смены режима. Ручных точек
   в UI нет, endpoint inputs и прочие неподдерживаемые поля API отклоняются.
4. Coverage ниже 51% блокирует FIT-only reconstruction, но тот же FIT с GPX проходит
   прежний workflow. Web использует значение и решение Core без собственного расчёта.
5. Паузы, approximate selection и partial результаты совпадают с CLI 022 без
   endpoint hints при одинаковых входах, policy/config и snapshots, кроме
   operational metrics. Prefix/suffix в FIT-only не достраиваются.
6. Retry/reload/refresh сохраняют режим; прежние двухфайловые jobs без новых
   полей metadata продолжают обрабатываться и отображаться.
7. Public schema/consumer показывают gate, gaps и результат согласованно;
   при отказе нет ложной ссылки на corrected FIT и заявления о полном восстановлении.
8. Access control, upload limits, cleanup/retention и запрет чувствительных логов
   распространяются на FIT-only jobs и результаты.
9. Проходят Web backend/frontend tests и pipeline regression suite. Browser smoke
   покрывает загрузку одного FIT, добавление/удаление GPX, отказ по coverage, partial
   результат и прежнюю загрузку двух файлов. Сетевые сбои сохраняют текущие правила
   graceful failure, не отменяя пригодный partial результат.
10. Отказ FIT-only gate возвращает инициатора на `/fix` с понятным сообщением и
    пустыми полями. Повторная попытка требует выбрать оба файла и создаёт новый
    job. Отдельное открытие отчёта отказа по ссылке сохраняет доступ к диагностике.
11. Валидный partial FIT доступен для скачивания; незаполненные начало/конец явно
    указаны. Такой результат не перенаправляет пользователя на форму.

При реализации зафиксировать фактические команды проверок, результаты browser smoke
и сравнения с CLI. Использовать синтетические fixtures; private FIT и производные
артефакты не коммитить. Deployment выполняется только по отдельному запросу.

## 8. Результат 023A

Реализован backend для обязательного `activity` и необязательного `course`.
Дубли, посторонние поля и ручные endpoints отклоняются; пустой/невалидный GPX
не переключает режим. SQLite хранит `has_course`; миграция старых jobs ставит
`true`, поэтому утраченный старый GPX остаётся ошибкой. Режим передаётся в worker
через `--fit-only` и сохраняется при recovery/reuse/refresh.

Worker использует общий pipeline с прежними OSM/DEM defaults и isolation.
Coverage settings передаются через окружение дочернего процесса и валидируются
Core. Gate-отказ публикует текущий outcome `unresolved` без corrected FIT;
решение Core сохраняется в приватном `private-processing-audit.json` с правами
0600, без HTTP-доступа. Public schema не расширялась.

Добавлены синтетические проверки upload/metadata/migration, coverage gate до
OSM/DEM/writer, серверной конфигурации и её передачи в subprocess, refresh,
доступа и retention. При одинаковых данных и offline OSM-кеше внутренний gap
восстанавливается, prefix/suffix остаются unresolved, результат побайтно совпадает
с CLI, timestamps и сохранённые координаты неизменны. Интеграционный тест
изолированного OSM worker выполняется только на Linux; на macOS реальный routing
проверяется прямым вызовом обработчика без изменения production isolation.

Границы: форма, тексты страниц, новый public report, отображение coverage и возврат
на `/fix` — 023B; browser acceptance и завершение общей приёмки — 023C.
Ручные точки относятся к 024. Core reconstruction и deployment не менялись.

Команды проверки из корня репозитория:

```bash
.venv/bin/python -m pytest tests web/tests -q
node --test web/tests/*.test.mjs
.venv/bin/ruff check .
.venv/bin/mypy src
git diff --check
```

Результаты 2026-09-18: Python — **927 passed, 7 skipped** (включая новый
Linux-only worker test); Node — **14 passed**. Ruff lint, mypy (65 source files),
`git diff --check` и форматирование изменённых Web-файлов проходят. Добавлен
41 тестовый случай: 40 выполнены, один требует Linux. Backend-критерии 023A
выполнены с указанной платформенной границей проверки; общая приёмка 023 впереди.

Форматирование изменённых Web-файлов проходит `ruff format --check`. Полная
команда `.venv/bin/ruff format --check .` выявляет две прежние проблемы:
`README.md` и `tests/test_fit_only_coverage.py`; обе воспроизводятся на содержимом
HEAD до изменений 023A. Эти файлы в рамках 023A не менялись.


## 9. Результат 023B

Одна форма `/fix` запускает обработку по FIT; одинаково заметный GPX-блок остаётся
открытым с подписью «Необязательно» и пояснением пользы маршрута. Неверный GPX
блокирует запуск до замены или явного удаления. Убраны тексты про два обязательных
файла и организаторов; обновлены главная и FAQ. Ручных точек нет.

Public schema v5 явно проецирует режим, Core coverage и безопасные причины,
а также типы gaps и их счётчики. UI показывает активное/покрытое время, отказ,
ограничения начала/конца, подробности внутренних участков и approximate/partial
результат. Отсутствующая геометрия GPX скрывает слой карты. Отчёты v1–v4 без новых
полей остаются читаемыми; эти сведения для них не придумываются.

Инициатор отмечается только в записи истории перехода после upload. При
`below_threshold`/`unavailable` эта запись заменяется на `/fix` с сообщением
в `history.state`, без query-параметров или сохранения файлов. Сообщение переживает
reload. Отдельное открытие ссылки не перенаправляется; partial FIT доступен
владельцу по прежним правилам. Версии изменённых browser assets обновлены вместе.

Проверки командами из раздела 8: **931 passed, 7 skipped** в Python,
**22 passed** в Node; Ruff lint, mypy и `git diff --check` проходят.
Добавлены 4 Python-сценария публичного coverage и 8 Node-проверок формы, навигации
и текстов. Прежние schema assertions обновлены на v5. Ограничение Linux-only
OSM isolation и две прежние проблемы общего форматирования остаются прежними.

Локальный browser smoke на синтетических данных проверяет форму и запуск с одним
FIT, реальный отказ 37,5% при пороге 51%, возврат на пустую форму, сохранение
сообщения при reload и отдельное открытие отчёта без redirect. Также проверен
partial-отчёт, подготовленный прямым вызовом обработчика с реальным offline OSM:
51 внутренняя точка восстановлена, по 20 точек начала/конца остались unresolved;
таблица, предупреждение approximate, карта без GPX и кнопка скачивания владельца
отображаются, ошибок JavaScript нет. Такой smoke не заменяет проверку Linux worker.
Критерии интерфейса и публичного отчёта 023B выполнены в указанном объёме.
Расширенная матрица end-to-end, Linux worker и итоговая приёмка остаются в 023C.
Core, ручные точки (024) и deployment в эту подзадачу не входят.

## 10. Результат 023C

Приёмка 2026-09-18 проверяет реализацию 023A–023B в Linux с настоящим
изолированным OSM worker и в локальном браузере. Изменения production-кода
для этой подзадачи не потребовались. Добавлен `web/tests/test_live_acceptance.py`:
четыре opt-in HTTP-проверки работающего сервиса с синтетическими файлами.

| Сценарий | Результат проверки |
| --- | --- |
| FIT без GPX | Запускается; для чистого FIT gate passed, отсутствуют фиктивный GPX и ложное скачивание |
| GPS ниже порога | Core блокирует reconstruction; инициатор возвращается на пустую форму с сообщением; reload сохраняет сообщение |
| Coverage unavailable | Понятная причина, без подмены на 0%; возврат на форму и повторный выбор файлов |
| Добавление/удаление GPX | FIT остаётся достаточным для запуска после удаления; оба блока видны сразу |
| Пустой/повреждённый GPX | Пустой файл блокирует кнопку; повреждённый непустой файл даёт ошибку обработки, без FIT-only fallback |
| FIT+GPX | Настоящая загрузка, очередь, worker, repaired-отчёт, GPX-слой и скачиваемый FIT; gate not_applicable |
| FIT-only partial / CLI parity | На offline OSM-кеше заполнена 51 внутренняя точка, по 20 точек краёв остаются unresolved; FIT побайтно совпадает с CLI |
| Сохранение данных | Тест Linux worker проверяет timestamps и все сохранённые координаты; края без hints не достраиваются |
| Owner / guest | Владелец получает FIT через GET/HEAD/Range; без cookie и с отдельной сессией все три варианта запрещены; публичный отчёт доступен |
| Переход по ссылке | Отдельное открытие отчёта отказа не перенаправляет; partial-результат остаётся на странице результата |

Browser smoke объединяет результаты 023B с повторной проверкой на Linux-сервисе:
неопределимое покрытие, повторная загрузка двух файлов, успешный GPX repair,
выбор/удаление GPX и ошибки пустого/повреждённого GPX. В проверенных сценариях
ошибок JavaScript не обнаружено. Migration/retry/refresh, allowlist публичной
схемы, upload limits, retention и сетевые ошибки покрыты regression tests.

Дополнительно пользователь просмотрел и принял реальный FIT-only результат
CHR KayaBayu без ручных точек: покрытие 68,917%, три внутренних пропуска заполнены
(1857 точек), prefix/suffix остаются unresolved (745 + 1672 точки). Результат
помечен approximate/partial. Отдельная проверка исходного и выходного FIT
подтвердила неизменность timestamps, 9500 сохранённых координат, датчиков и
неизвестных/developer fields. Приватные FIT, отчёты и идентификаторы jobs
не включаются в репозиторий.

Команды Node, Ruff, mypy и `git diff --check` приведены в разделе 8. Для живого
локального сервиса выполнена команда из [Web README](../web/README.md#проверки):

```bash
WARPBUSTER_ACCEPTANCE_ORIGIN=http://127.0.0.1:8023 \
```
