# Task 023 — FIT-only Web Integration

Статус: ТЗ подготовлено; реализация не начата.
Обязательная предпосылка: [Task 022](022-fit-only-reconstruction.md) завершена и
принята по pipeline/CLI tests и внутренним JSON/HTML отчётам. Нельзя начинать
реализацию 023 параллельно с незавершённой 022.

## 1. Цель и границы

Добавить в Web принятый в 022 режим восстановления по одному FIT с optional
пользовательскими стартом/финишем либо общей точкой одного кольца.

023 интегрирует готовый общий pipeline. Coverage, detector, OSM/DEM selection,
allocation, endpoint semantics и FIT writer не реализуются заново в Web.
Поведение определяется завершённым contract 022, включая порог 51% по активному
времени только без GPX и неизменяемые timestamps/сохранённые координаты.

До начала 023 существующий Web уже работает с обновлённым pipeline через прежний
FIT+GPX вызов. Совместимость этого вызова — acceptance 022, а не исправление в 023.

## 2. Форма и API

- FIT обязателен, GPX optional. Сохранить прежний сценарий загрузки FIT+GPX.
- Без GPX разрешить optional start, finish либо явную общую точку одного кольца.
  Пользователь может задать только старт или только финиш.
- Ввод через карту/координаты; показать выбранные точки и возможность их удалить.
  Общая точка несовместима с отдельными start/finish; близость концов не включает
  кольцевой режим автоматически. Несколько кругов не поддерживаются.
- Кратко объяснить: край достраивается только при соответствующей точке; точка
  условно относится к началу/концу записи, результат может быть примерным.
- При GPX пользовательские endpoints не передаются; несовместимый прямой API-запрос
  отклоняется по contract 022. Переключение формы не отправляет скрытые старые точки.
- Проверять конечность и диапазоны координат, дубли/неизвестные поля и допустимые
  комбинации параметров, сохраняя существующие upload/resource ограничения.
- Предоставленный невалидный или пустой GPX остаётся ошибкой GPX и не переключает
  запрос молча в FIT-only. Не создавать фиктивный `course.gpx`.

## 3. Job, worker и конфигурация

Persisted job metadata явно хранит наличие course и пользовательские endpoints,
достаточные для повторения запроса. Worker передаёт их в принятый pipeline 022;
отсутствие GPX передаётся явно. Режим и coverage разрешает Core, не Web-эвристика.

Сохранить обработку прежних двухфайловых jobs без новых metadata полей. Для retry,
refresh и повторного чтения результата не терять endpoints и не менять режим.
Обновить предположения об обязательном GPX во всех затронутых Web adapters.

Добавить серверную настройку `minimum_observed_gps_coverage_percent` с default 51%,
общей с Core validation и действием только на FIT-only. Дополнительные параметры
coverage передаются согласно принятому config 022. Пользовательский Web-регулятор
порога не требуется. Сохранить существующие OSM/DEM defaults, isolation и budgets.

## 4. Публичный результат и приватность

Обновить allowlisted public schema и её frontend consumer согласованно. Не
сериализовать внутренний Core report целиком. Результат показывает:

- режим, статус coverage gate, исходную долю GPS и требуемый порог;
- активную и покрытую GPS длительность, причины невозможности расчёта;
- пользовательские точки, их использование и допущение привязки ко времени;
- исходные/восстановленные участки и статусы internal/prefix/suffix gaps;
- approximate/partial результат, причины отказов и доступные validation/diff
  сведения в рамках публичной проекции.

При `below_threshold`/`unavailable` показывать диагностику без ссылки на несуществующий
corrected FIT. `unavailable` не означает 0%; с GPX gate — `not_applicable`.
Отказ одного gap не маскирует успешно восстановленные другие участки. Не называть
результат полным или точным, если это не следует из принятого contract.

Endpoints имеют ту же приватность, контроль доступа и retention, что FIT geometry:
не попадают в operational logs, удаляются вместе с job/input metadata при cleanup.
Публичные errors не раскрывают private paths, сырые config или exception dumps.

## 5. Этапы и предполагаемые файлы

1. **023A — Web backend:** optional GPX upload, endpoint validation, persisted
   metadata, worker/config и совместимость прежних jobs.
2. **023B — UI/public reports:** форма, карта/координаты, публичная схема, состояния
   результата и понятные сообщения об ограничениях.
3. **023C — Acceptance:** backend/frontend tests, end-to-end и локальный browser
   smoke, regression прежнего FIT+GPX workflow.

Ожидаемые области изменений: `web/backend/warpbuster_web/`, Web frontend,
`web/tests/`, frontend tests и Web documentation. Изменения общего Core допустимы
только для выявленной интеграционной необходимости с сохранением acceptance 022;
новые reconstruction policies не входят в 023.

## 6. Acceptance criteria

1. Предпосылка 022 подтверждена отчётом реализации и приёмкой внутренних отчётов.
2. Web принимает один FIT, FIT со start/finish/одной общей точкой и прежнюю пару
   FIT+GPX; отсутствующий course не приводит к обращению к фиктивному файлу.
3. Невалидный GPX и неверные endpoint inputs дают понятную ошибку без скрытой смены
   режима. Скрытые точки формы не передаются после перехода в GPX-сценарий.
4. Coverage ниже 51% блокирует FIT-only reconstruction, но тот же FIT с GPX проходит
   прежний workflow. Web использует значение и решение Core без собственного расчёта.
5. Endpoints, паузы, approximate selection и partial результаты совпадают с CLI 022
   при одинаковых входах, policy/config и snapshots, кроме operational metrics.
6. Retry/reload/refresh сохраняют режим и точки; прежние двухфайловые jobs без новых
   полей metadata продолжают обрабатываться и отображаться.
7. Public schema/consumer показывают gate, endpoints, gaps и результат согласованно;
   при отказе нет ложной ссылки на corrected FIT и заявления о полном восстановлении.
8. Access control, upload limits, cleanup/retention и запрет чувствительных логов
   распространяются на новые endpoint metadata и результаты.
9. Проходят Web backend/frontend tests и pipeline regression suite. Browser smoke
   покрывает загрузку одного FIT, ввод/удаление точек, отказ по coverage, partial
   результат и прежнюю загрузку двух файлов. Сетевые сбои сохраняют текущие правила
   graceful failure, не отменяя пригодный partial результат.

При реализации зафиксировать фактические команды проверок, результаты browser smoke
и сравнения с CLI. Использовать синтетические fixtures; private FIT и производные
артефакты не коммитить. Deployment выполняется только по отдельному запросу.

## 7. Вне scope

Новая reconstruction logic, изменение порога/endpoint semantics относительно
принятой 022, несколько кругов, waypoint editor, изменение timestamps, AI/LLM и
deployment. Подготовка этого ТЗ не означает завершения 022 или разрешения начать 023.
