# Task 011B — Pause-aware reconstruction

## Проблема

Реконструкция сейчас отклоняет целый GPS gap при любом пересечении с остановкой
таймера. Нормальные остановки на забеге блокируют пригодные GPX-кандидаты, хотя
время, опорные точки и данные движения до/после паузы сохранены.

## Объём и инварианты

- Удалить blanket rejection по наличию паузы. GPX matching остаётся локальным.
- Не менять Integrity Detector, timestamps, timer events, датчики и достоверные
  координаты. GPX не участвует в доказательстве corrupted. Не добавлять records.
- Единая vendor-neutral модель активного времени для всех reconstruction gaps:
  internal, prefix, suffix. `--fill-missing-from-course` сохраняет свою семантику.
- Без routing, переинтерпретации FIT-полей и общего ослабления signal checks.

## Таймер

1. Использовать известные события timer start/stop/stop_all/stop_disable/
   stop_disable_all и группы таймеров. Не использовать timer_trigger для определения
   остановки. Повторный stop не сдвигает начало, повторный start идемпотентен.
   В файле с единственной явной группой отсутствие event_group не создаёт второй
   независимый таймер; при нескольких явных группах эту принадлежность не угадывать.
2. Объединять пересекающиеся паузы, учитывать только пересечение с окном gap
   вместе с anchors. Паузы на точной внешней границе не блокируют окно.
3. Активное время = исходное время минус объединение пауз; timestamps неизменны.
   Не интегрировать скорость через выключенный таймер.
4. Незакрытая пауза внутри окна — локальная неопределённость состояния таймера,
   а не разрешение заморозить всю оставшуюся запись. Отказывать только этому gap.
   Финальный stop ровно на последнем timestamp не является такой неопределённостью.
5. Не считать паузу доказательством неподвижности. Рост пригодной distance stream
   на полностью остановленном интервале — явное локальное противоречие. Не исправлять
   distance/coordinates для его сокрытия. В текущем этапе даже небольшой положительный
   прирост требует диагностики; допуск для дрейфа не вводить без отдельного обоснования.

## Распределение пути

- Приоритет прежний: пригодная distance → пригодная speed → оценка по времени.
- Distance: сохранять исходную шкалу, плато дистанции даёт плато положения;
  проверять движение за активное время, в том числе внутри gap.
- Speed: интегрировать только активные части интервалов. Значения внутри остановки
  не использовать как самостоятельное доказательство движения (могут быть stale).
- Time fallback: только когда прежние правила разрешают fallback, по накопленному
  активному времени, с явной отметкой estimated. Противоречие пригодных distance/speed
  с длиной GPX не обходить временем.
- Проверять длину пути / активное время и восстановленные переходы, включая
  пройденную длину вдоль пути; длинная пауза не оправдывает невозможную скорость.
- При нулевом активном времени нельзя распределять ненулевой путь. Отклонение
  candidate не меняет независимый scope удаления corrupted координат.
- Без пауз результаты распределения и FIT repair должны остаться прежними.

## Отчёты

Для planned/applied/unresolved gaps: elapsed, paused, active seconds, число пауз,
открытое состояние таймера; для кандидатов — метод распределения. Время охватывает
окно вместе с anchors. В console/JSON/общем HTML-шаблоне видны конкретные причины:
незакрытая пауза, нет активного времени, противоречие distance и паузы, невозможное
движение за активное время. Не выдавать timer pause за поломку timestamp.

## Acceptance criteria

- [x] Internal/prefix/suffix gaps с нормальной паузой восстанавливаются при остальных
  выполненных условиях; distance, speed и active-time allocation протестированы.
- [x] Несколько, пересекающиеся, повторные и граничные паузы учитываются без двойного
  вычитания; records во время остановки и их отсутствие поддержаны.
- [x] Незакрытое/противоречивое состояние и нулевое активное время дают локальный
  отказ; соседние gaps и достоверные координаты остаются нетронутыми.
- [x] Невозможная активная скорость не скрывается длинной паузой; GPX mismatch и
  ambiguity safeguards сохранены. Детектор не меняется.
- [x] Lossless FIT round-trip сохраняет исходник, timestamps, events, sensors,
  unknown/developer fields и определения; CRC/diff проходят.
- [x] Полный suite, Ruff, mypy проходят; синтетические регрессии обязательны.
  Приватные файлы используются только для дополнительной проверки, не задают алгоритм.
- [x] Отчёты содержат timing audit и метод распределения; локальная пакетная сводка
  обновлена. Файлы без пауз дают прежние результаты.
