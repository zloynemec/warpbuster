# Task 011A — Независимое доказательство физически недостижимого GNSS-хвоста

## Проблема и границы

После невозможного перехода координаты могут образовать плавный, но физически
недостижимый участок и не вернуться к нормальной записи до конца активности.
Требование правой здоровой опоры и правдоподобного bridge тогда блокирует не только
reconstruction, но и invalidation. Это самостоятельное расширение Integrity Detector,
а не изменение GPX matching в Task 011 и не начало routing / Task 012.

## Правило

- Существующие двухопорные доказательства сохраняются и имеют приоритет.
- Новый поиск запускается на непокрытом IMPOSSIBLE переходе. Опорой для удаления
  может быть только точка после `tail_anchor_min_normal_transitions` последовательных
  соседних NORMAL переходов (default 15).
- Для каждой координаты после входа проверяется недостижимость от неизменной опоры:
  `geodesic_distance > absolute_impossible_speed_mps * elapsed_seconds + tail_position_error_budget_m`.
  Дополнительный суммарный запас погрешности координат — 50 м по умолчанию.
  Используется физический предел профиля (для running 25 м/с), не median pace и не
  reconstruction bridge limit. При отсутствии предела правило выключено.
- Время учитывается полностью, включая missing records. Невалидное/немонотонное время
  и границы continuity обрывают доказательство; timestamps не исправляются.
- Каждая positioned запись в области удаления должна оставаться недостижимой.
  Missing записи не превращаются в corrupted coordinates. Уверенность — MEDIUM.
- Первая достижимая точка прекращает расширение области удаления. Координаты после
  неё сохраняются. Возобновление trusted anchors требует ещё 15 последовательных
  NORMAL переходов между точками, достижимыми от прежней опоры; одиночная достижимая
  точка не считается восстановлением сигнала. До подтверждения anchors запрещены.
- Неподтверждённый вход со слабым левым контекстом не разрешает удаление, но его
  плавная смещённая компонента не может стать опорой для удаления настоящего возврата.
- Поиск линейный: предвычисленные контекст/границы continuity и непересекающиеся
  forward scans. Полный FIT-by-FIT поиск отсутствует.

## Pipeline и аудит

`unreachable_tail` имеет отдельный reachability proof, `bridge=null` и отсутствие
правой опоры. Маска повторно проверяет недостижимость всех positioned записей один
раз на интервал. Маркер/диагностика без доказательства не разрешает invalidation.

Удаление не требует курса, repair candidate или успешного reconstruction. Records,
timestamps, sensors и неизвестные FIT поля сохраняются. Исходные пропуски и удалённые
координаты образуют общую пустоту. Опциональный GPX provider работает по существующим
правилам, включая локальные проверки сигналов и opt-in course endpoint assumption.
Отказ provider не восстанавливает удалённые ошибочные координаты обратно.

JSON/console/HTML показывают опору, число недостижимых координат, предел скорости,
запас погрешности, минимальный выход за допустимый радиус и причину окончания proof.
Общий HTML-шаблон сохраняется. FIT diff и gap audit отдельно показывают invalidated,
filled и unresolved.

## Acceptance

- [x] Синтетические terminal/missing-entry/smooth-displaced случаи распознаются.
- [x] Реальное движение, длительный достижимый пропуск, слабая опора, generic profile,
  неоднозначное время и continuity не приводят к необоснованному удалению.
- [x] Настоящий возврат не удаляется; восстановление доверия не расширяет bad scope.
- [x] Маска одинакова с GPX и без него; invalidation-only и GPX completion проходят
  lossless FIT round-trip, без изменения времени, сенсоров и допустимой дистанции.
- [x] Общие JSON/HTML/console отчёты поддерживают proof без фиктивного bridge.
- [x] 20k records detection + mask <5 с; весь предыдущий suite, lint/type checks зелёные.

Проверка: `.venv/bin/pytest -q`, `.venv/bin/ruff check src tests scripts`,
`.venv/bin/ruff format --check src tests scripts`, `.venv/bin/mypy src`, `git diff --check`.

Ограничения: без правой опоры уверенность максимум MEDIUM; плавная физически достижимая
ошибка сама по себе не доказывается; данные distance/speed не считаются независимыми
датчиками без известного происхождения. География моря, конкретный трек, GPX/OSM/DEM
не входят в условия доказательства. Изменение политики GPX signal mismatch не входит
в эту задачу.
